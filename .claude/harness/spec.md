# Spec — PDF 개념 요약 노트 모듈 (PKS 원자화 모듈) — 2026-08-16

> `/plan`으로 작성. 사용자 sign-off 완료(2026-08-17).

## 목표 (1문장)
사용자가 스캔+OCR된 PDF의 페이지 범위와 주제를 지정하면, 도구가 해당 영역의 그림·텍스트를 **로컬에서** 추출하고 LLM이 텍스트를 요약해 **프론트매터가 채워진 마크다운 요약 노트(들)**를 생성하며, 대화형·직접 편집으로 다듬은 뒤 사용자가 결과물을 자신의 옵시디언 vault로 **직접 옮길 수 있다.**

## 배경 / 맥락
개인이 스캔해 둔 학습용 PDF를 PKM(옵시디언)에 요약 정리해 축적하려 한다. 이 모듈은 더 큰 **PKS(개인 지식 시스템)의 한 모듈**이며, 검색/색인(Qdrant)은 **예정된 후속 모듈**이다. 깨끗한 모듈 경계를 유지하되 산출물이 후속 색인 모듈에 그대로 소비되도록 **Qdrant-ready**로 만든다.

## In Scope
- 스캔+OCR PDF 지정 → **페이지 범위** + **주제 프롬프트** 입력
- **로컬 레이아웃 추출**(PaddleOCR-VL): 그림 크롭 + 연관 주석/본문 텍스트를 **읽기 순서**로 추출 (외부 OCR 벤더로 이미지 미전송)
- 추출 **텍스트만** LLM에 전달 → **1~N개 요약 노트**(개수는 프롬프트가 결정, 보통 1개)
- 각 노트 = 확정 프론트매터 + 본문 요약 + 관련 그림 `![[파일명]]` 첨부
- **대화형 리파인**(후속 프롬프트) + **직접 마크다운 편집** 병행(같은 상태 공유; 직접 편집분이 다음 프롬프트 기준)
- 결과물(마크다운 + 그림 파일) **묶음 내려받기/복사** → 사용자가 수동으로 vault에 이동
- **`LayoutExtractor` 교체가능 인터페이스**: 엔드포인트 설정만 바꿔 서버리스 GPU ↔ 로컬 전환
- 웹앱: **FastAPI 백엔드 + React(Vite) 프런트엔드**

## Out of Scope
- vault 자동 저장 / vault 경로·파일명 충돌 관리
- `[[링크]]` 연결 및 기존 vault 노트 인식
- 그림 내용의 vision 해석(그림은 첨부만)
- Qdrant 벡터 색인/검색(후속 모듈)
- 블록 클릭/lasso 정밀 선택(2차), 자유 드래그, 전체 페이지 썸네일 내비게이션
- 다중 사용자/동시성, 반응형 모바일

## 사용자 / 시나리오
- **누가:** 개인 학습자(본인)
- **언제:** PDF로 공부하다 특정 페이지 내용을 PKM에 정리하고 싶을 때
- **어디서:** 개인 PC 브라우저(로컬 웹앱). 추출 백엔드는 서버리스 GPU 호출(추후 로컬)

## 완료 조건 (관찰 가능)
- [ ] 스캔 PDF 지정 + **페이지 범위 + 주제 프롬프트** 입력 가능
- [ ] 지정 페이지의 그림을 **크롭 이미지**로, 텍스트를 **읽기 순서**로 추출 (외부 OCR 벤더 미전송)
- [ ] **추출 텍스트만** LLM에 전달되어 요약 노트 생성 (이미지 외부 미전송)
- [ ] 생성 노트에 확정 프론트매터(`id/title/source/pages/topic/tags/created`) 채워짐
- [ ] 관련 그림이 본문에 `![[파일명]]`으로 첨부됨
  - [ ] **프롬프트 지시 또는 직접 편집**으로 반복 수정 가능, 직접 편집분이 다음 프롬프트 기준
  - 
- [ ] 프롬프트에 따라 노트가 **1개(기본) 또는 여러 개** 생성
- [ ] 완성물(마크다운 + 그림) **묶음 내려받기/복사** 가능
- [ ] 추출 엔진 엔드포인트를 **설정만 바꿔 서버리스 GPU ↔ 로컬 교체** 가능

**확정 프론트매터 스키마:**
```yaml
---
id: <안정적 고유 ID>
title: <주제/개념 제목>
source: <원본 PDF 파일명>
pages: [42, 43, 44]
topic: <사용자 입력 주제 프롬프트>
tags: []
created: 2026-08-16
---
```

## 프론트엔드 요구 (화면 / 상호작용)
> 스택 = **React(Vite)**. 시각 미리보기는 표준 웹기술(PDF 페이지=PDF.js, 노트=마크다운 렌더러)로 구현하며 **특정 디자인 시스템 강제 없음**. 룩앤필·컴포넌트 라이브러리 선택은 구현 재량.

**단일 화면, 좌우 2분할 레이아웃**

*좌측 — 소스 패널*
- [ ] PDF 열기(업로드 또는 로컬 경로 지정)
- [ ] **PDF 페이지 뷰어(온디맨드)** — 전체를 렌더하지 않고 **입력한 범위 페이지만** 렌더; 범위 변경 시 해당 페이지만 재렌더
- [ ] **페이지 범위 입력**(예: `42-44`)
- [ ] **주제 프롬프트 입력란**
- [ ] **[생성] 버튼** + 진행 상태(추출 중 / 요약 중 / GPU 콜드스타트 대기)

*우측 — 작업 패널*
- [ ] **요약 노트 미리보기**(렌더된 마크다운)
- [ ] **직접 편집** 마크다운 소스 창(편집분 상태 반영)
- [ ] 노트 여러 개면 탭/목록 전환
- [ ] 첨부 **그림 미리보기**
- [ ] **리파인 대화 패널**(후속 프롬프트 + 응답 히스토리, 현재 노트 반영)
- [ ] **[내보내기] 버튼**(마크다운 + 그림 묶음)

*상태/에러*
- [ ] 추출 실패·텍스트 0건 등 명확한 안내, 처리 중 인디케이터

**비고:** `playwright.config.ts`의 `webServer`가 `npm run dev`(Vite) + 포트를 호출하도록 `package.json`에 `dev` 스크립트를 맞춘다.

## 테스트 케이스 (LLM·GPU는 mock으로 결정적 실행)
1. **정상:** 42–44쪽 + 주제 "경사하강법" → 프론트매터 채워진 노트 1개 + 그림 첨부, 묶음 내려받기 가능
2. **에지(텍스트 0건):** 범위에 텍스트 블록 없음 → "요약할 텍스트 없음" 안내, 빈 요약 저장 방지
3. **에지(에러):** 추출 엔진 실패/타임아웃 → 오류 표시, 상태 손상 없음, 재시도 가능
4. **에지(노트 분할):** 프롬프트 "두 개로 나눠" → 노트 2개, 각각 독립 프론트매터
   - *동시성: 개인 단일 사용자 전제로 범위 밖(순차 처리)*

## 하드 임계값
- **성능(개인 저사용):** 추출(콜드스타트 포함) < 90초, 리파인 응답(텍스트만) < 15초
- **품질:** 린트 0, 타입 에러 0, 기존 테스트 전부 통과
- **커버리지:** 신규 핵심 로직(추출 파싱→노트 조립, 프론트매터 생성, 리파인 상태 관리) 단위 테스트

## 비기능 요구
- **보안/PII:** 원본 **이미지는 로컬/자기 인스턴스에서만** 처리(외부 OCR 벤더 전송 금지). 외부 LLM엔 **추출 텍스트 발췌만**. 로그에 원문 미기록
- **접근성:** 최소 요건(키보드로 주요 조작)
- **i18n:** 한국어 우선
- **모바일:** 데스크탑 전용

## 명시된 가정
- 개인 단일 사용자, 저사용(월 ~200p)
- 대상 PDF는 스캔+OCR(페이지 전체 래스터, OCR 레이어 품질 불확실 → 로컬 파서 재추출)
- 로컬 GPU 없음 → 서버리스 GPU(Beam/Modal, 무료 크레딧 실질 $0)로 시작, 장비 구매 시 로컬 이전(동일 컨테이너)
- 옵시디언 vault = 로컬 마크다운 폴더, 도구는 vault에 쓰지 않음
- "원자화" = 요약 정리; 노트는 자기완결 요약, v1 링크 없음
- 이 모듈은 PKS의 한 모듈; Qdrant는 후속 모듈

## 미해결 / 후속 항목
- **구현 초기 스파이크:** 서버리스 GPU 제공자 택일(Beam vs Modal), PaddleOCR-VL의 **figure 영역 출력 형식**·하드웨어 요구 확인
- LLM 모델 최종 확정(1차 단일, Opus 계열 권장)
- 그림 묶음 전달 세부(zip vs 개별) — 구현 재량
- **후속 모듈/스프린트:** `[[링크]]`·기존 노트 인식, 블록 클릭/lasso, 특정 그림 vision, **Qdrant 색인 모듈**, vault 자동 저장
- **CLAUDE.md 프로젝트 설명 갱신**(현 RAG/Qdrant 중심 → 실제 1차 기능 반영)
